# 验证记录

这些记录区分最初的网页端部署和发布到仓库的通用代码，避免把本机测试等同于任意 ChatGPT 账号都可用。

## 已验证环境

- Linux x86_64，CachyOS，KDE Plasma/KWin 6.7.5，Wayland。
- Google Chrome 153。
- Node.js 26.8.2；Node.js 24.19.0 另外通过单元与无桌面 MCP 集成检查。
- Python 3.14；CI 另配置 Python 3.12、Node.js 22/24。

其他系统组合仍需要独立验证。安装程序当前只提供 Linux amd64 的 Tunnel release。

## 网页端原部署

维护者已在 ChatGPT 网页端实际完成连接器创建、文件写入/读回、全屏和活动窗口截图采集，以及浏览器工具调用。浏览器控制功能已由网页端操作确认可用。

该环境的 ChatGPT Code Mode 报告可接收 JPEG 数据，但未获得可靠视觉输入，因此没有把截图理解标为通过。通用代码保留同一 MCP 图像返回方式及这一限制。

## 通用代码

本仓库使用独立配置和持久浏览器目录，全部工具启用时发现 53 个唯一工具。真实集成脚本在临时 HOME 下执行：

- 读取原服务全部 2 个 UI 资源；验证资源模板、提示模板及日志接口。
- 文本写入与读回，中文逐字核对；通过 Desktop Commander 读取合成图片。
- 显示器信息、全屏与活动窗口截图的 JPEG 解码。
- 可见浏览器读取页面结构，通过快照元素引用点击、中文填表、上传、下载。
- 浏览器页面截图、标签页管理、全新 MCP 进程重启后的 Cookie 与本地存储保留。

上述图形集成完成 **24 次成功工具调用**。9 项 JavaScript 单元与兼容性测试另覆盖配置、凭据环境清理、分页、命名冲突、排队取消、图像库和 Excel 条件格式读写。47 项 Python 测试覆盖安装、配置保留、凭据原子写入、健康检查、代理、超时清理和真实 systemd 解析。

在包含空格和 `%` 的临时用户目录中执行完整安装：实际从官方 release 下载并校验 Tunnel、按锁文件安装 npm 依赖，再启动安装后的 MCP。四种功能组合分别返回 53、26、51、28 个工具；生成的 systemd 服务通过 `systemd-analyze verify` 检查。测试没有创建凭据或启用正式服务，临时安装已删除。

发布前用 `npm audit --omit=dev` 检查锁定依赖，更新 sharp 和 uuid 后结果为零已知公告。该结果仅反映检查时的公告数据库，不能替代后续维护。

测试使用临时网页和资料目录，结束后清理；仓库不包含真实截图、测试用户目录或浏览器登录资料。GitHub Actions 的当前状态请以仓库 Actions 页面为准。

## 本地 Work 调度验收（2026-10-12）

新增桥接通过真实 MCP 工具在专用的已有本地 Work 聊天中完成 **9 项检查**。运行环境为 Linux、Node.js 26.11.1，桌面执行器 CLI 版本为 `0.162.0-alpha.17.2`。测试连接正在运行的桌面内部 IPC，没有重启桌面应用、创建新聊天或改变目标聊天权限。

| 检查 | 实际结果 |
| --- | --- |
| MCP 工具发现 | 62 个唯一工具，其中 9 个 `work_*` 工具 |
| 同用户桌面 IPC | 成功连接已运行的桌面应用 |
| 本地 Work 发现 | 列表包含所指定的专用聊天 |
| 技能发现 | 返回 75 个本地技能及路径 |
| 派发、幂等、等待与取回结果 | 相同 `request_id` 重试复用同一任务和执行轮，取得该轮完成回复 |
| 同一聊天续派 | 第二项任务在同一聊天完成并返回对应结果 |
| 指定插件与技能 | Work 实际调用所选桌面连接器的 `get_config`，并执行所选技能的官方文档核实流程 |
| 指定执行轮中断 | 只中断该派发任务的已确认执行轮，最终状态为 `interrupted` |
| 真实上下文压缩 | 取得新的、已完成的手动 `contextCompaction` 事件 |

这次检查由 `scripts/verify-work.mjs` 经本地 MCP stdio 层执行，耗时 127.2 秒，验收脚本 RSS 约 75–83 MiB；在独立可见终端打印进度，结束后关闭终端。它验证真实桌面会话执行链路，不能代替每个 ChatGPT 账号刷新插件后的网页端工具发现验收。私有报告、聊天 ID、测试提示和插件私有引用均未提交到仓库。

原有 MCP 默认配置回归仍发现 53 个工具，文件写入/读回、图片和资源接口通过。部署测试为 49 项通过，包含 Work 默认关闭、显式启用及升级保留配置。新增单元测试覆盖跨实例任务锁、派发结果不确定时不重发、执行轮关联、审批/输入等待状态以及压缩完成和失败状态。

此记录仅覆盖已有本地 Work 聊天和上述桌面版本；云端 Work、自动创建聊天和其他桌面版本不在本次验收范围内。内部 IPC 的版本耦合仍按 [配置说明](configuration.md#本地-work-调度) 处理。

## 模型与思考强度选择验收（2026-10-12）

`0.2.1` 通过真实 MCP 派发验证 `model=gpt-6.1-sol`、`reasoning_effort=medium`。结果的 `effective_model`、`effective_reasoning_effort` 来自关联执行回合参数，分别为 `gpt-6.1-sol`、`medium`；未指定覆盖参数的后续任务也保持相同设置。此次模型专项验收共 7 项通过，耗时 11.68 秒。

Node.js 单元测试 58 项、部署测试 49 项通过，新增覆盖省略参数的旧幂等记录兼容、模型/强度三种覆盖组合、保留协作模式及指令、修改参数后拒绝重复派发，以及无效参数在发送前拒绝。

复现时选择自己的专用本地 Work 聊天：

```bash
node scripts/verify-work.mjs --thread-id <自己的本地Work聊天UUID> --model gpt-6.1-sol --reasoning-effort medium --out model-verification.json
```

### 真实聊天模式主模型验收

另新建了一个真实 ChatGPT 聊天，聊天主模型为 GPT-6、思考强度为“极高”，未选 Pro。主模型通过连接器自行填写 `work_send` 的模型和强度参数，以 `gpt-6.1-sol` / `medium` 在指定本地 Work 聊天中执行任务。

该会话完成了桥接/聊天/技能发现、结构化插件和技能选择、文件写入、主聊天独立读回、精确回合中断、真正的手动上下文压缩，以及压缩后的同聊天后续派发。关联回合元数据与文件结果一致；后续任务也确认模型和思考强度保持所指定设置。

测试同时记录到间歇性 Tunnel 连接超时：文件工具重试后恢复，第一次后续任务完成但返回读取超时，另一次明确的新任务最终读取成功。因此本记录证明功能链路可完成，不代表传输始终无超时。中断发生在等待工具启动之前，覆盖的是指定回合中断能力。查询目标的本地标题与桌面显示标题不同，本次以指定 UUID 精确定位。

## 稳定性优化验收（2026-10-12，0.2.2）

固定升级到官方 Tunnel `0.0.16`，发布 ZIP 同时核对 GitHub 资产摘要及 `SHA256SUMS.txt`，运行二进制版本确认通过。新增稳定性规则的 Node.js 测试共 **86 项通过**，Python 部署测试 **49 项通过**。实际 MCP 兼容检查完成 5 次成功工具调用，重复带编号追加只写入一次；部署后的本地 Work 专项 7 项通过。

沿用真实 ChatGPT 聊天，主模型思考强度为“极高”、未使用 Pro，以 `gpt-6.1-sol` / `medium` 派发两个本地 Work 任务。完整验证了带编号追加的回执去重、相同编号不同内容拒绝、相同请求重复派发返回同一执行回合、默认 5 秒等待、旧 45 秒请求夹到 10 秒、0 秒缓存读取、超时后任务继续执行、原生文件与等待工具，以及同 Tunnel 父子插件读取。

最后 5 次串行读取 **5/5 成功**，聊天报告本轮 **0 次连接超时**。本机私有日志捕获 **23 次调用**，最长 `work_wait` 为 **5,180 ms**；两个预期写入参数冲突被拒绝，其余本机调用无错误，所有调用均有开始和完成记录。日志隐私检查通过，不含参数、文件路径、文件内容或异常原文。写入回执在同编号重复和不同参数拒绝后仍为 `completed`，测试文件只有一行。

只读临时故障的退避恢复、`Retry-After`、取消、断线后写入回执不重放、跨进程并发去重以及取消时保留写锁，另由可控故障测试验证。真实网络故障未人为注入；单次成功样本不证明永久稳定，也不能据此确定此前超时的网络根因。
